# Version 1.69.0 – Ein Nachbau, der enger ist als der Vertrag

Drei Fassungen lang hieß die Frage: *was die Seite schreibt, wieder
hineingeben.* Diesmal etwas, bei dem es kein Zurück gibt – die **HTML-
Ausgaben**. Niemand liest sie je wieder ein; jemand doppelklickt sie.

Davon gibt es drei:

| | woher |
| --- | --- |
| das ganze Handbuch | Designstudio, „Handbuch als HTML sichern" |
| die Blätter zum Drucken | Designstudio, „Als HTML zum Drucken" |
| Format **HTML** | Register Output |

Angesehen hatte sie noch nie jemand.

## Die Frage bei HTML ist eine andere

Ein PDF trägt alles in sich. Eine HTML-Datei kann **nachladen** – eine
Schrift, ein Bild, ein Stylesheet –, und dann ist sie im Haus hinter der
Firewall leer. Das ist bei einer Seite, die die Inhaltsrichtlinie des
Artifacts ohnehin an der Leine hält, leicht zu übersehen: die *Anwendung*
darf nichts nachladen, aber die Datei, die sie schreibt, wäre eine andere
Sache.

Also: jede Datei ohne Netz öffnen, jede Anfrage nach draußen abweisen und
nennen.

```
=== handbuch.html ===
Bilder: 11 von 11 geladen · Überschriften: 16 · Text: 6085 Zeichen
Nichts von draußen – die Datei steht für sich.

=== blaetter.html ===
Bilder: 2 von 2 geladen · Nichts von draußen.

=== ablauf.html ===
Bilder: 3 von 3 geladen · Nichts von draußen.
```

**Alle drei stehen für sich.** Kein Nachladen, keine fehlende Schrift,
keine leere Seite hinter der Firewall. Das war die wichtigste Frage, und
die Antwort ist gut.

## Was dabei auffiel

Dieselbe Kette noch einmal, mit der Sprache auf **Englisch** (F-66):

```
=== handbuch-en.html ===
Sprache am Dokument: en        ← richtig

=== blaetter.html ===
Sprache am Dokument: de        ← auch auf Englisch
Bildtext: Blatt | Blatt
```

Das Handbuch macht es richtig (seit 1.48.0: `lang="${sprache}"`). Die
beiden anderen schrieben `lang="de"` als festen Text – auch für eine
englische Unterlage.

Das ist keine Kleinigkeit für den, der sie liest: ein Vorleseprogramm
spricht sie deutsch aus, der Browser trennt nach deutschen Regeln, und ein
Übersetzungswerkzeug überspringt sie. Dazu hieß der Bildtext dreimal
„Blatt" – für ein Vorleseprogramm drei gleiche Bilder.

Jetzt: `lang` folgt der Ausgabesprache, und der Bildtext heißt `Blatt 1/3`
bzw. `Sheet 1/3`.

## Warum keine Prüfung das sah

Hier liegt der eigentliche Befund.

`downloads.save` nimmt laut Vertrag
`string | Blob | ArrayBuffer | ArrayBufferView`. Die Seite gibt beides: das
Handbuch als Blob, die Blätter zum Drucken als **Zeichenkette**.

Der Nachbau in den Prüfungen kannte nur den Blob:

```js
const text = await auftrag.data.text();   // eine Zeichenkette hat kein .text()
```

Eine Zeichenkette ließ ihn scheitern. `uebergebeDatei` fängt das ab und
meldet „fehlgeschlagen" – still, denn niemand wartete darauf. Die Datei kam
nie in `window.__abgelegt`, und **keine Prüfung konnte je in sie
hineinsehen**. Genau dort stand dann auch das falsche `lang`.

> Ein Nachbau, der enger ist als der Vertrag, verbirgt Code.

Das ist dieselbe Form wie 1.67.0, wo die Prüfdatei **ein** Bild trug und
darum den Unterschied zwischen „Text des Dokuments" und „Text neben dem
Bild" nicht zeigen konnte. Nicht die Prüfung war falsch – das, womit
geprüft wurde, war zu klein.

## Und ein Stolperstein zum zweiten Mal

Beim Messen: die Meldung *während* des Rechnens heißt

```
Servicevertrag anlegen wird gerechnet – 1 von 1 …
```

und danach

```
1 Dokument(e) gerechnet · 3 Blätter.
```

Wer auf `/gerechnet/` wartet, trifft die erste und drückt zu früh. **Drei
Browserprüfungen** taten genau das und kamen bisher damit durch, weil die
Rechnung dort schnell ist. Sie warten jetzt auf `Dokument(e) gerechnet`.
Denselben Fehler hatte ich eine Fassung zuvor mit „wird gelesen …" gemacht.

## Grenzen

* Geprüft wurde mit Chromium. Wie Safari oder ein älterer Internet Explorer
  im Haus die Datei zeichnet, steht hier nicht.
* „Nichts von draußen" heißt: diese Dateien, aus diesem Bestand. Ein Logo,
  das jemand als Hausmarke einbindet, wird eingebettet (F-62) – eine Datei
  mit einem sehr großen Logo wurde nicht gemessen.
* Die Blätter und das Output-HTML tragen **keinen Text**, nur Bilder. Das
  ist so gebaut und kein Fehler: sie sind das gerechnete Blatt, nicht sein
  Inhalt. Wer Text will, nimmt das Handbuch oder die Word-Datei.
