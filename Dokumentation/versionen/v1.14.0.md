# Version 1.14.0 – Beleg bilden in der Seite

Punkte 6 und 7 der Bestandsaufnahme „was fehlt“.

## Was fehlte

Das Archiv lebt von Belegen: zwei Aufnahmen und die Begründung dazwischen. Die
Seite konnte Aufnahmen machen, sammeln, ablegen, zurückholen – aber keinen
Beleg daraus bilden. Das ging nur im Projekt, von Hand, in
`data/eintraege.json`. Wer die Aufnahmen hatte, hatte die Arbeit noch vor sich,
und die vier Begründungsfelder standen nirgends, wo sie jemand ausfüllen
konnte.

## Die Werkbank

Im Eingang öffnet **Beleg bilden** eine Werkbank:

1. **Paar wählen** – zwei Auswahlfelder, vorgeschlagen werden die älteste als
   *vorher* und die neueste als *nachher*. Beide Bilder stehen nebeneinander.
2. **Angaben** – vorausgefüllt mit dem, was die Aufnahmen wissen: Projekt,
   Seite, Kategorie, Browser, Datum, Schlagworte. Der Titel bleibt leer, er
   beschreibt die Änderung, nicht das Bild.
3. **Begründung** – Anlass, Änderung, Wirkung, Quelle. Ohne sie ist ein Beleg
   wertlos, darum sind sie Pflicht und je mindestens 20 Zeichen lang.
4. **Kennzahlen** – Name, Einheit, vorher, nachher, Richtung. Daneben steht
   laufend die gerechnete Wirkung (`+82,1 %`), dieselbe Rechnung wie im Archiv.

Unter dem Formular steht in einem Satz, was noch fehlt; der Knopf
**Belegentwurf sichern** bleibt bis dahin gesperrt. Geprüft wird wie im
Bestand – unter anderem:

| Regel | warum |
| --- | --- |
| Vokabular für Projekt, Kategorie, Status, Viewport | sonst weist die Datenprüfung den Beleg ab |
| Vorher-Aufnahme nicht jünger als die Nachher-Aufnahme | sonst sind beide vertauscht |
| Bei Status *verworfen*: das Wort im Wirkungstext | ein verworfener Beleg muss sagen, warum |
| Kennzahl ganz oder gar nicht | eine halbe Zahl ist keine Messung |

## Punkt 7: der Weg in den Bestand

Die Seite kann `data/eintraege.json` nicht schreiben – sie läuft im Browser
des Betrachters, ohne Netz und ohne Projektzugriff. Das bleibt so. Statt
dessen entsteht eine Datei, die genau dort hineinpasst:

```json
{ "belegentwurf": 1, "eintrag": { … , "screen": null },
  "aufnahmen": { "vorher": { "bild": "data:image/jpeg;…" }, "nachher": { … } } }
```

`screen` steht auf `null` – Archetyp und Schalter für die gezeichneten
Aufnahmen entstehen im Projekt, und die Seite behauptet nichts, was sie nicht
weiß. Die beiden echten Bilder liegen daneben: sie sind die Vorlage für diese
Beschreibung, nicht der Inhalt des Bestands. Der Skill `beleg-aufnehmen`
beschreibt die fünf Schritte von der Datei zum Beleg.
