# Version 1.54.0 – `aufnahme.js` geteilt

Der letzte Posten aus der [Durchsicht](../durchsicht.md), der ohne
Nutzungsdaten zu entscheiden war. Nach `markieren.js` (1.52.0) die zweite
große Datei: in `aufnahme.js` steckten **Aufnahmestudio und Eingang**.

## Aus einer Datei werden zwei

| Datei | Zeilen | Inhalt |
| --- | --- | --- |
| `aufnahme.js` | 1 395 | Speicher, Kompaktmodus, Quelle, Ausschnitt, Auslöser, Formular, Studio |
| `eingang.js` | 830 | Eingang, Werkbank „Beleg bilden“, Eingangsdialog, Ordnerband, Sichern |

Anders als bei `markieren.js` ließ sich hier nicht einfach schneiden: die
**Verdrahtung** am Ende war *eine* Funktion, die beide Hälften anschloss.

## Die Verdrahtung: zwei Funktionen, ein Aufruf­ort

Aus `verdrahteAufnahme()` werden zwei:

```js
// aufnahme.js – erklärt, aber nicht aufgerufen
function verdrahteAufnahme() { /* Quelle, Ausschnitt, Auslöser, Tastatur, Einfügen */ }

// eingang.js – am Ende, da wo bis 1.53.0 der eine Aufruf stand
function verdrahteEingang() { /* Suche, Sortierung, Sichern, Werkbank, Ordnerband */ }

verdrahteAufnahme();
verdrahteEingang();
```

Beide werden **an derselben Stelle** aufgerufen wie bisher der eine Aufruf.
Das ist der Punkt: der Text liegt in zwei Dateien, der Start läuft in
derselben Reihenfolge. Dass `verdrahteAufnahme()` aus `eingang.js` heraus
erreichbar ist, liegt an der gemeinsamen Klammer – Funktionserklärungen
werden vorgezogen, `const` und `let` nicht.

## Die Probe

Eine zeichengleiche Seite wie bei 1.52.0 war hier nicht zu haben: die
Verdrahtung wurde geteilt, also hat sich Text bewegt. Stattdessen die Probe
über den **Bestand der Zeilen**: welche Codezeile ist verschwunden, welche
ist neu?

```
Zeilen, die verschwunden sind: 1
  - /* ---------- Verdrahtung ---------- */      (die alte Überschrift)

Zeilen, die neu sind: 27
  + function verdrahteEingang() {
  + }
  + verdrahteEingang();
  + 24 Zeilen Kommentar und Überschriften
```

**Keine einzige ausführbare Zeile ist verloren gegangen**, und neu sind nur
die drei, die die zweite Verdrahtungsfunktion ausmachen. Der Rest ist
Kommentar.

Dazu die 479 Prüfungen, die bei einer geteilten Verdrahtung mehr zu sagen
haben als bei einem reinen Verschieben: sie drücken in der Begehung jeden
sichtbaren Befehl in jeder der dreizehn Ansichten.

## Damit ist die Durchsicht abgearbeitet

| Befund | Erledigt |
| --- | --- |
| Dreizehn Register in einer Reihe | 1.51.0 – fünf Aufgaben |
| Vier Wege, den Bestand weiterzugeben | 1.53.0 – die Übersicht |
| Zwei Dateien mit zu vielen Ansichten | 1.52.0 (`markieren.js`) und hier |

Offen bleibt nur, was ohne Benutzung nicht zu entscheiden ist: die **Probe
mit den sechs Verdachtsfällen** auf tote Funktionen. Die Durchsicht sagt,
wie sie ginge – die Knöpfe nicht entfernen, sondern an eine Stelle rutschen,
die man aufklappen muss. Fehlen sie niemandem, ist der Fall klar.

Dreizehn Oberflächendateien sind jetzt vierzehn, und keine ist mehr über
1 400 Zeilen lang außer `core.mjs` – die bleibt lang, weil sie ohne Browser
prüfbar ist, und das ist ihr Preis wert.
