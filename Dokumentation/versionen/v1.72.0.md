# Version 1.72.0 – Dieselbe Falle, eine Datei weiter

Seit 1.15.0 steht im Kern ein Kommentar, der eine Falle beschreibt:

> `iTXt` statt `tEXt`, weil nur der UTF-8 kann – `tEXt` verstümmelte
> „Prüfung" zu „PrÃ¼fung".

Die Falle wurde dort erkannt und umgangen. Eine Datei weiter stand sie
offen.

## Die Übersicht als CSV

Das Register Verzeichnis legt neben den Bildern eine `index.csv` – die
Tabelle, die jemand in **Excel** öffnet. Sie ist UTF-8, mit Semikolon als
Trenner (richtig für ein deutsches Excel) und sauber in Anführungszeichen
gesetzt. Nur fehlten ihr drei Bytes am Anfang.

So liest Excel sie ohne diese drei Bytes:

```
AUF-2026-001;;;VollstÃ¤ndigkeit;PrÃ¼fung der Signaturwege;…;GebÃ¼hr GrÃ¶Ãe
```

So ist sie gemeint:

```
AUF-2026-001;;;Vollständigkeit;Prüfung der Signaturwege;…;Gebühr Größe
```

Excel rät das Format einer CSV, und ohne **Byte Order Mark** rät es
Windows-1252. Genau dieselbe Verstümmelung, genau dasselbe Wort wie im
Kommentar von 1.15.0.

Drei Bytes beheben das. Dazu **CRLF** nach RFC 4180, weil Excel selbst so
schreibt; ein Zeilenumbruch *in* einer Zelle bleibt ein einzelnes `\n` in
Anführungszeichen und beendet die Zeile nicht.

## Was dabei geprüft wurde und blieb

| Datei | |
| --- | --- |
| `index.json`, Beipackzettel, `strecken.json` | **kein** BOM – JSON darf keines haben |
| BPMN | deklariert `encoding="UTF-8"` selbst |
| die HTML-Ausgaben | `<meta charset="utf-8">` im Kopf |
| OCR-Textdatei | kein BOM: sie geht in einen Editor, nicht in Excel |

Die CSV war die einzige Datei, die ihr Format weder erklärt noch mitteilt –
sie muss es dem Leser überlassen, und der rät falsch.

## Und ein Verdacht, der sich wiegen ließ

Die Durchsicht führt sechs Funktionen als wahrscheinlich tot. Nummer sechs
war der **Kontaktbogen** (F-23), und der Verdacht galt nicht seinem Zweck,
sondern seiner Größe: „eine HTML-Datei mit allen Bildern".

Nachgewogen, mit elf Bildern aus dem Messfilm:

| Datei | Größe |
| --- | --- |
| **Kontaktbogen** | **306 kB** |
| Handbuch als Word | 615 kB |
| Handbuch als HTML | 758 kB |
| Blätter als HTML | 1640 kB |

Der Bogen ist der **kleinste** Weg nach draußen, nicht der größte. Er
bettet die Vorschauen ein, nicht die vollen Bilder – das stand immer im
Code, nur hatte es nie jemand nachgerechnet.

Dabei ist auch etwas über die Durchsicht selbst zu sehen: ihre Liste führte
*„zu groß"* und *„wird nicht gebraucht"* als eine Art Verdacht. Das erste
lässt sich in einer Minute messen, das zweite braucht Wochen echter
Benutzung. Von den sechs Verdachtsfällen bleiben jetzt **fünf**.

## Grenzen

* Geprüft wurde, dass die Datei ein BOM trägt und CRLF benutzt – **nicht**,
  wie Excel sie tatsächlich öffnet. Hier steht kein Excel.
* Das BOM hilft Excel; ein Werkzeug, das es nicht erwartet, sieht ein
  unsichtbares Zeichen vor „id". Jeder UTF-8-Leser wirft es weg, und das
  gilt für `csv`-Bibliotheken ebenso.
* Der Kontaktbogen wurde mit **elf** Bildern gewogen. Bei hundert wächst er
  linear – 306 kB sind kein Freibrief, sondern eine Zahl für elf Bilder.
