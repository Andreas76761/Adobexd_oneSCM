# Version 1.77.0 – 798 Textstellen, zwei Zahlen

Es gibt eine Kontrastprüfung, und sie ist nicht falsch. Sie sieht an:
den Grund der Seite gegen die Schrift, und die Überschrift einer Karte.

**Zwei Stellen.** Die Frage gilt allen.

## Gemessen

WCAG 2.1 AA verlangt **4,5:1** für gewöhnlichen Text und **3:1** für
großen (ab 24 px, oder ab 18,66 px fett). Das ist keine Geschmacksfrage,
sondern eine Zahl – also jeden sichtbaren Text in vierzehn Ansichten
gegen den Grund, der wirklich hinter ihm liegt:

| | unter der Grenze |
| --- | --- |
| helles Thema | **798** |
| dunkles Thema | **71** |

Das dunkle Thema ist das bessere – und genau das war das einzige, das
geprüft wurde.

## Eine Ursache

798 Befunde, aber nur drei Verhältnisse: 3,11 – 3,32 – 3,82. Immer
dieselbe Farbe auf vier verschiedenen Gründen.

```css
--tinte-3: #77839A;   /* die dritte Tinte: Hinweise, Labels, Zahlen */
```

| auf | |
| --- | --- |
| `--flaeche` #FFFFFF | 3,82:1 |
| `--flaeche-2` #F6F7FA | 3,57:1 |
| `--grund` #EDEFF3 | 3,32:1 |
| `--flaeche-3` #E4E8EF | **3,11:1** |

Kein einziger Wert erreicht 4,5. Und weil `--tinte-3` die Farbe jedes
Hinweises, jedes Labels und jeder Zahl daneben ist, hängen 798
Textstellen an dieser einen Zeile.

Im dunklen Thema dasselbe, milder: `#7B8698` schafft 5,06 auf dem Grund,
aber nur 3,92 auf `--flaeche-3`.

## Zwei Zahlen geändert

```css
--tinte-3: #5F687A;   /* hell:   4,56 bis 5,60:1 */
--tinte-3: #8691A5;   /* dunkel: 4,54 bis 5,86:1 */
```

Beide bleiben in derselben Farbrichtung und zwischen `--tinte-2` und dem
Grund – die Abstufung Überschrift / Text / Nebensache bleibt also
erhalten. Danach:

```
=== hell ===    Zusammen: 0
=== dunkel ===  Zusammen: 0
```

Angesehen wurde es auch, in beiden Themen: die Gliederung mit ihren
1153 Stellen liest sich wie vorher, nur sind die Zahlen daneben jetzt
zu lesen.

## Zwei Riegel

**Gerechnet, ohne Browser.** Eine Build-Prüfung nimmt jede `--tinte-*`
gegen jede `--grund`/`--flaeche*` aus der Stilvorlage, in beiden Themen,
und rechnet das Verhältnis aus: 24 Paare, in Millisekunden. Gegengeprobt
– mit dem alten Wert fällt sie.

**Gemessen, im Browser.** Eine Browserprüfung fährt alle vierzehn
Ansichten in beiden Themen und misst jeden sichtbaren Text gegen seinen
wirklichen Grund. Sie fängt, was die Rechnung nicht sieht: eine Farbe,
die nicht aus einem Token kommt, oder ein Text auf einem Grund, den
niemand vorhergesehen hat.

Die alte Prüfung mit ihren zwei Stellen bleibt stehen. Sie prüft etwas
anderes – dass das dunkle Thema überhaupt dunkel ist – und kostet nichts.

## Grenzen

* Gemessen wird **Text gegen Grund**. Nicht geprüft sind Ränder,
  Trennlinien und Symbole: für die gilt 3:1, und sie haben keine
  Textfarbe, an der sich das ablesen ließe.
* Der Grund ist der erste Vorfahr, der deckt. Ein Text auf einem Bild
  oder auf einem Verlauf wird damit falsch gerechnet; in dieser Seite
  kommt beides nicht vor.
* Die Ansichten standen **leer**. Farben, die nur an echten Daten
  erscheinen – ein Status, eine Marke –, sind nicht mitgemessen.
* 4,5:1 ist die Grenze für AA, nicht für AAA (7:1). Der Fließtext liegt
  weit darüber, die dritte Tinte jetzt knapp über AA.
